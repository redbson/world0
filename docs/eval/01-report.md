# LongRun 报告：长期运行的 Agent 里，World 0、传统记忆与直接上下文有什么区别

> 设计、系统、指标、公平性措施与局限见 [README.md](README.md)；完整表格在 [results/tables.md](results/tables.md)
> 与 [results/readers.md](results/readers.md)。本文只写结论、支撑结论的数字，以及每个结论成立的条件。
> 设计者同时是 World 0 的作者；下面凡是对 World 0 不利的结果都照写，凡是评测台无法回答的问题都标为"未测"。

## 0. 先说答案

1. **在能装进上下文、也负担得起的时候，直接把全部历史放进上下文是最准确的做法，任何记忆系统都没有超过它。**
   理想读者下综合分 0.87（全部差距来自"桥接"一类里两义并存的纯度，不是漏答）；真实 LLM 读者读完整历史得 **1.00**
   （130 个问题）。代价是 token：1 000 个事件约 2.4 万 token，3 000 个事件约 9.5 万，6 000 个事件（约 40 万）已经
   装不进 128k 窗口，此时它的准确率随窗口下降（32k 0.67 → 64k 0.77 → 128k 0.81）。
2. **传统记忆模块的区别是"在哪一步付出代价、在什么条件下崩"**：检索（RAG）在写入时几乎免费、读时靠相似度，准确率随历史变长
   和文本变啰嗦下降（0.77 → 0.66；每事件填充 400 token 时 0.54）；带任务标签的事实库 / 图只用约 200 token 就到 0.82，
   且不随视野、闲聊、冗长变化，但**吃抽取误差**（抽取错 30% 时 0.82 → 0.58）；按任务维护的摘要 / 状态文档在 600–1 200 token 上
   得 0.91–0.96，但**离开正确的任务标签就崩**（无标签 0.55 / 0.41，错标签 0.45 / 0.30）。
3. **World 0 在这个评测里没有超过配置合理的结构化记忆。** 调好的版本（`world0_tuned`，约 600 token）综合分 0.59，
   高于只做一跳的事实库（0.57）和不处理撤回的图（0.56），低于带任务标签的事实库 / 时序图（0.82，配对检验 10 个种子全输，
   Δ = −0.22），也低于 RAG（0.74）。它的强项是**多跳结构**：depth 3 的激活把两跳邻域召回到 0.93、依赖闭包 F1 到 0.93
   （其中"闭包"一项对手只做两跳，见 §3.3 的说明）；弱项是**修订**和**情景细节**：撤回后旧主张仍被展示，严格记分 ≈ 0，
   真实读者在 100% 的问题里提到了过期主张；票据号这类情景细节按设计为 0。
4. **World 0 出厂的 `render()` 对真实读者几乎不可用**：读者的回答 54–59% 是概念 id 而不是名称（解析 id 之后 F1 才从 0.23 升到 0.64），
   同一个投影用紧凑格式渲染后是 0.80。这是渲染工程问题，不是投影的问题，但它是用户今天拿到的默认行为。
5. **评测没有覆盖 World 0 声称的几项能力**：任务标签在这里对 World 0 没有任何可测的影响（精确 / 缺失 / 错误 = 0.59 / 0.59 / 0.61），
   所以"上下文敏感"没有被检验；遗忘、视角、别名与概念身份、跨会话漂移也没有被检验。这些是"未测"，不是"没有"。
6. **成本**：World 0 每个事件的写入约 4 ms、状态约 2.9 MB（H = 1 000），事实库是 0.007 ms 与 12 KB（约 500 倍 / 240 倍）；
   读一次 0.03–34 ms，相比一次 LLM 调用可以忽略。三者里真正贵的是直接上下文的**推理 token**，其次是结构化系统的**抽取**
   （本评测没有计入任何系统的抽取成本）。

## 1. 三种做法到底差在哪

| | 直接上下文 | 传统记忆（检索 / 摘要 / 事实库 / 图） | World 0 |
|---|---|---|---|
| 保存什么 | 原文 | 原文片段、摘要、抽取出的事实 | 抽取出的**概念与带类型的关系**，附信念、证据计数、成熟度 |
| 写入时做什么 | 追加 | 索引 / 摘要 / 抽取入库 | 抽取、概念解析、共现学习、衰减结算、晋升 |
| 读取时做什么 | 全部交给读者 | 相似度或实体匹配取 top-k；或整份摘要 | **激活**：从入口概念沿类型化关系扩散，再按任务与多样性选出一个小的局部视图 |
| 成本随什么增长 | 历史长度（token） | 历史长度（检索）或几乎不增长（摘要 / 事实库） | 概念与关系的数量；写入最贵 |
| 主要失败方式 | 窗口装不下；被填充词稀释；每次查询都付全价 | 检索漏掉多跳；摘要丢细节；事实库吃抽取误差 | 撤回后旧主张仍在；细节没有位置；渲染不够紧凑；抽取误差 |
| 撤回 / 修订 | 读者自己看到"更正" | 时序图 / 事实库删除旧事实（严格得分 1.00）；检索靠新近度（0.90–0.98） | **软撤回**：旧主张被削弱但仍展示 |
| 能回答"票据号是多少" | 能 | 事实库 / 检索能 | **不能**（按设计不在职责内） |

## 2. 评测在测什么（一段话）

隐藏世界是若干个领域，每个领域是一张带类型的小概念图（依赖 / 包含 / 冲突 / 使能），另有一词多义的桥接概念、
会被修订的依赖、带票据号的事件和 25% 的闲聊；每个 seed 一个世界、一条事件流，所有系统读到同样的内容。
查询在检查点生成：`focus`（入口概念两跳内的局部视图）、`chain`（依赖闭包）、`bridge`（桥接概念在当前领域的主张，
记召回 × 语义纯度）、`stale`（被修订的依赖现在是什么，严格记分）、`detail`（票据号，不计入综合分）。金标准只含
**Agent 已被告知且仍为真**的内容。综合分 = 前四类头号指标的均值。主实验 10 个 seed（H = 1 000）；
区间为对 seed 的 95% t 区间；系统间比较按 seed 配对，精确符号翻转检验并做 Holm 校正；World 0 的 depth 与 reflect 频率
**只在 dev seeds（100–104）上选定**，报告用 test seeds（0–9）。

## 3. 结果

所有数字为 H = 1 000、预算 1 200 token、理想读者（读者恰好读懂上下文里写着的东西），除非另注；token 是系统实际放进提示词的量（结构化系统只返回相关内容，不会用满预算）。

### 3.1 直接上下文

| | 综合分 | token | 备注 |
|---|---|---|---|
| `full_context`（≤128k） | 0.87 ± 0.01 | 36 447 | 桥接 0.54：全文里两个义项都在，纯度低；其余接近满分 |
| `window`（最近若干事件填满预算） | 0.16 ± 0.03 | 1 149 | 预算 4 800 时 0.40 |

- **随视野**：`full_context` 0.89 → 0.87 → 0.84 → 0.81（H = 300 / 1 000 / 3 000 / 6 000），窗口开始装不下之后下降；
  大世界（40 领域 × 40 概念，H = 6 000，已知状态 2.3 万 token）0.82，此时它读的是 10.8 万 token。
- **窗口装不下时**（H = 6 000，全流 40.7 万 token，理想读者只读装得下的部分）：32k **0.67**，64k **0.77**，128k **0.81**；
  `fact_task` 用 410 token 得 0.80，`rag` 0.66。也就是说，历史超出窗口之后，直接上下文的优势按窗口大小消失。
- **被填充词稀释**：每事件填充 400 token 时 0.74（其余 0.87）；`window` 0.03。结构化系统读的是抽取结果，不受影响。
- **真实读者**（同一个模型读整份历史，130 个问题）：**1.00**（24 023 token）；H = 3 000 的 60 个问题也是 **1.00**，读的是
  95 430 token。真实读者没有理想读者在桥接上的纯度损失，所以直接上下文在准确率上没有对手，剩下的只有成本和窗口。

### 3.2 传统记忆

| 系统 | 综合分 | token | 主要特征 |
|---|---|---|---|
| `rag`（BM25） | 0.74 ± 0.03 | 1 166 | 预算 600 时 0.68；H = 6 000 降到 0.66；填充 400 降到 0.54；撤回 0.98 |
| `rag_recency`（Generative-Agents 配方） | 0.71 ± 0.04 | 1 167 | 不比普通 RAG 好；撤回 0.90 |
| `summary_buffer`（扁平摘要） | 0.23 ± 0.05 | 1 139 | 扁平摘要没有用 |
| `summary_task`（按任务摘要） | 0.96 ± 0.02 | 1 099 | **依赖任务标签**：无标签 0.55，错标签 0.45 |
| `state_doc`（当前状态文档，当前任务优先） | 0.94 ± 0.03 | 1 076 | 同上：无标签 0.41，错标签 0.30；细节 1.00 |
| `factstore`（Mem0 式，一跳，无标签） | 0.57 ± 0.02 | 63 | 撤回 1.00；细节 1.00 |
| `fact_task`（+ 任务标签、两跳） | 0.82 ± 0.01 | 223 | 不随视野 / 闲聊 / 冗长变化；**吃抽取误差** |
| `kg_temporal`（带失效与出处的图） | 0.82 ± 0.01 | 223 | 与 `fact_task` 相同；`kg_static`（不处理撤回）撤回 0.00、综合 0.56 |

- **视野**：`rag` 0.77 → 0.74 → 0.67 → 0.66，`fact_task` 0.83 → 0.82 → 0.81 → 0.80，`summary_task` / `state_doc` 0.92–0.97 平稳。
  越长的历史，越需要写入时做过整理的系统。
- **抽取误差**（漏抽 p、抽错类型 p/2、每事件多出一条虚假关系 p、漏掉撤回 p）：p = 0.3 时 `fact_task` 0.82 → **0.58**，
  `state_doc` 0.94 → 0.66，`factstore` 0.57 → 0.41；文本系统（RAG、全上下文、窗口）不变。**结构化记忆的准确率上限是抽取器的准确率**，
  而这一项成本在本评测里没有计入。
- **"只展示至少被陈述两次的主张"作为抗噪手段是负面结果**：`fact_task_s2` 在 p = 0.05 时就掉到 0.52，因为它同时丢掉了真实的只说过一次的冷门知识。
- **任务标签**是这类系统的命门：`summary_task`、`state_doc` 是所有系统里最强的，但只在标签正确时；`fact_task` 用标签做过滤
  （错标签下不变，因为它同时按实体匹配）。

### 3.3 World 0

| 变体 | 综合分 | token | focus | chain | bridge | stale |
|---|---|---|---|---|---|---|
| `world0`（出厂：depth 2、`render()`） | 0.43 ± 0.04 | 973 | 0.32 | 0.51 | 0.59 | 0.28 |
| `world0_compact`（同一投影，紧凑渲染） | 0.56 ± 0.01 | 460 | 0.89 | 0.82 | 0.52 | 0.00 |
| `world0_tuned`（dev 上选：depth 3、每 25 次轻量 reflect） | 0.59 ± 0.01 | 632 | 0.92 | 0.93 | 0.52 | 0.00 |
| `world0_depth1` / `depth3` | 0.34 / 0.60 | — | 0.47 / 0.94 | 0.44 / 0.95 | 0.46 / 0.53 | 0 / 0 |
| `world0_reflect` | 0.54 | — | 0.88 | 0.76 | 0.50 | 0 |
| `world0_notask` / `world0_focus` | 0.56 / 0.56 | — | 0.90 | 0.83 | 0.51 / 0.52 | 0 |

配对对比（`world0_tuned` 减去对手，预算 1 200，综合分；10 个 seed，Holm 校正后全部 p < 0.03）：

| 对手 | Δ | 赢的 seed |
|---|---|---|
| `full_context` | −0.28 | 0/10 |
| `summary_task` / `state_doc` | −0.36 / −0.35 | 0/10 |
| `fact_task` / `kg_temporal` | −0.22 / −0.22 | 0/10 |
| `rag` / `rag_recency` | −0.15 / −0.12 | 0/10 |
| `factstore`（一跳、无标签） | +0.02 | 10/10 |
| `kg_static` | +0.03 | 10/10 |
| `window`、`summary_buffer` | +0.43、+0.36 | 10/10 |
| 出厂 `world0` | +0.17 | 10/10 |

预算 600 时 `tuned` 对 `rag` 是 −0.08（0/10），对 `rag_recency` +0.01（不显著）。

- **结构上的好处是真的，但这个评测里对手同样能做到。** 出厂 → depth 3 把 focus 从 0.32 拉到 0.94，chain 从 0.51 拉到 0.95：
  多跳激活确实是 World 0 的价值所在。但 `fact_task` 的 focus 是 1.00，chain 只有 0.73 是因为它**配置为两跳**（依赖闭包需要更深）；
  一个不限深度的图遍历会追平。所以"chain 0.93 对 0.73"应读作"World 0 把深度当成了可调参数"，而不是"World 0 独有的能力"。
- **视野与规模**：`tuned` 0.60 / 0.59 / 0.57 / 0.56（H = 300 → 6 000），随视野缓慢下降，斜率与 `fact_task` 一样；
  大世界 0.55（`fact_task` 0.84），**在已知状态装不进一个提示词时，紧凑的结构化视图（约 600 token）仍然有用，
  但不比一个带任务标签的事实库更好。**
- **抽取误差**：p = 0.3 时 0.59 → 0.43，相对降幅（−27%）与 `fact_task`（−29%）相同；**没有可测的鲁棒性优势**。
- **闲聊 / 冗长**：几乎不变（0.59–0.61）——结构化系统的共同优点。
- **任务标签**：精确 / 缺失 / 错误 = 0.59 / 0.59 / 0.61，`notask` 变体 = 紧凑版。**在这个评测里 World 0 的任务条件对结果没有可测的影响**，
  这不等于任务条件没用：入口概念本身已经决定了领域，评测里也没有"同一概念在不同任务下含义不同"的查询（一词多义的桥接查询靠的是关系类型，不是任务标签）。
- **调参**：dev seeds 上 depth 3 显著优于 depth 1 / 2（0.565 对 0.33 / 0.52）；reflect 频率 0 对 25 只差 0.005（0.565 对 0.570），
  在 5 个 dev seed 上无法区分。这一版按规则选了 25，上一版的代码状态下选了"从不"。两者在测试集上同为 0.59–0.60。
- **reflect 在这里略有害**（`world0_reflect` 0.54 对 0.56）：修剪与衰减丢掉了只被说过一次的真实关系——评测的金标准只含被告知且仍为真的内容，
  遗忘没有收益。这不能推出"遗忘无用"，只能说明评测里没有需要遗忘的东西。

### 3.4 修订（撤回）

| 系统 | 只展示当前 | 两者都展示且当前信念更高 | 两者都展示（未分辨） | 严格得分 | 宽松得分 |
|---|---|---|---|---|---|
| `full_context`、`fact_task`、`kg_temporal`、`summary_task`、`state_doc` | 100% | — | — | 1.00 | 1.00 |
| `rag` | 98% | 0% | 2% | 0.98 | 0.98 |
| `kg_static` | 0% | 0% | 100% | 0.00 | 0.00 |
| `world0_compact` / `tuned` | 0% | 84% | 13–14% | **0.00** | 0.83 |
| 出厂 `world0` | 29% | 32% | 8% | 0.28 | 0.59 |

**World 0 的撤回是软的**：一次 "Correction: X no longer depends on Y" 会削弱旧关系的信念，但不删除它，所以旧主张仍被展示，
只是当前主张的显示信念更高（84% 的问题里如此）。严格记分要求"旧主张不出现"，所以是 0；读者能不能靠信念分辨，取决于读者。
**真实读者**（紧凑渲染）在 100% 的这类问题里**提到了**过期主张，但 75% 答对了当前的那条——所以不是灾难，但也不是"撤回"。
这是 World 0 目前最清楚的设计缺口（§6）。

每个（问题, 上下文）一份独立文件，读者只读这一份，金标准放在单独的清单里，文件名经哈希打乱。**这一阶段的上下文是在修复 F7
（惰性回收）之前生成的**；紧凑与调好的 World 0 在 F7 前后的理想读者结果相差不超过 ±0.01，出厂 `world0` 的上下文在 F7 之后更长
（见 §5），所以这里出厂 `world0` 一行只作参考。

## 4. 该选哪个

| 情形 | 建议 | 依据 |
|---|---|---|
| 历史能装进窗口、每次查询付得起全价 | **直接上下文** | 真实读者 1.00；没有抽取误差、没有整理成本 |
| 历史超出窗口，或每次查询要省 token | **带任务标签的事实库 / 时序图，或按任务维护的状态文档** | 200–1 100 token 得 0.82–0.96；前者不吃标签但吃抽取，后者吃标签 |
| 需要情景性细节（票据号、原话） | **检索或事实库（保留出处），或直接上下文** | World 0 与摘要类得 0 |
| 修订、撤回必须干净 | **时序图 / 事实库，或全文** | 严格得分 1.00；World 0 目前是软撤回 |
| 任务标签不可靠 | 事实库 / 图 / World 0；**避开 `summary_task`、`state_doc`** | 无标签 0.55 / 0.41 |
| 抽取器不可靠（p ≥ 0.2） | 文本系统（RAG、全文）；结构化系统全部下降约 28% | 与系统无关的共同弱点 |
| 需要"用少量 token 给出一个带信念、带类型的局部概念视图"，且愿意接受 World 0 的写入成本 | World 0（紧凑渲染，depth 3） | 约 600 token 得 0.59；不随视野、闲聊、冗长变化；真实读者 0.80 |

## 5. 这些结论在什么条件下成立

- **合成世界**：名字唯一、无别名 / 同义词 / 指代；金标准由生成器定义（两跳球、依赖闭包、领域内主张）。结构化基线（`fact_task`、`kg_*`）用的就是
  与金标准同构的遍历，所以它们的 focus 是 1.00；这偏向它们。
- **抽取与链接是给定的**：结构化系统读生成器给的抽取结果（可注入误差，但不是真 LLM 抽取），实体链接是精确子串匹配。
- **读者阶段规模有限**：4 个 seed、130 + 60 个问题，同一个模型；并且**是在 F7 之前的代码上生成的**。
- **代码版本**：所有研究在 `e3c23ab`（含 F7）上重跑；读者阶段除外。F7 之后，出厂 `world0` 的渲染在"从不 reflect"的世界里更长
  （概念在事件上成熟，"Core Understanding" 段带描述与链接），预算 1 200 时综合分 0.45 → 0.43、token 1 049 → 973、focus 0.36 → 0.32；
  紧凑 / 调好的变体在 ±0.01 内。调好的版本的 reflect 频率随代码状态从"从不"变成"每 25 次"（见 §3.3，两者无法区分）。
- **World 0 的其余功能没有被评价**：视角、reflect 的社群与色场步骤、概念身份与合并 / 拆分、任务条件下的相关性重排、遗忘的收益。
- 压缩格式是作者写的；它把"投影"与"渲染开销"分开，但部分优势来自渲染工程。token 数是估计（`chars/4` 作为敏感性并列报告）。

## 6. World 0 该改什么（按这份评测的证据排序）

1. **给出厂 `Projection.render()` 一个紧凑风格**（并给"关联"列表设上限）：出厂渲染对真实读者 0.23（解析 id 后 0.64），紧凑渲染 0.80，
   而 F7 之后默认世界里概念更早成熟，"Core Understanding"段每个概念带描述与链接，同一个 15 概念视图从约 1 380 增到 3 180 token。
2. **硬撤回**：显式的"更正 / 不再"应当让旧主张退出展示（状态标为 retracted，或权重直接归零并从视图剔除），而不是只削弱信念；
   目前严格得分 ≈ 0，读者 100% 会看到过期主张。
3. **关系身份按（源, 目标, 语义类型）**：当前同一对概念、同一轴上的重标会覆盖标签；修订类事件因此不能干净地表达"换了一个依赖对象"。
4. **相关性截断，而不是把预算填满**：结构化系统只返回相关内容（150–650 token），World 0 出厂会一直填到预算（973）而召回并不上升
   （预算 2 400 时反而从 0.43 降到 0.37）。
5. **支持度感知的展示**：只被陈述一次的主张与被陈述十次的主张目前在渲染里差别很小；抽取误差下这决定了噪声进不进视图
   （注意"至少两次才展示"作为硬过滤是负面结果，应当是软权重）。
6. **读取时的结算**：事件之间激活读取的是存储的置信度而不是结算后的值，reflect 频率会改变两次使用之间的投影排序（论文 §13）。
7. **补测**：需要一个真正区分"上下文敏感"的评测（同一概念在不同任务下含义不同的查询）、遗忘有收益的评测（大量过时信息）、
   视角与别名的评测；没有它们，World 0 的核心主张只能说"未被反驳"，不能说"已被支持"。
