# LongRun 报告：长期运行的 Agent 里，World 0、传统记忆与直接上下文有什么区别

> 设计、系统、指标、公平性措施与局限见 [README.md](README.md)；完整表格在 [results/tables.md](results/tables.md)
> 与 [results/readers.md](results/readers.md)。本文只写结论、支撑结论的数字，以及每个结论成立的条件。
> 设计者同时是 World 0 的作者；下面凡是对 World 0 不利的结果都照写，凡是评测台无法回答的问题都标为"未测"。
> 本文是第四版：第三版的结论（World 0 落后带任务标签的事实库 0.22）在评测暴露的三个缺陷修复后不再成立，
> 修复与重跑过程见 §7。

## 0. 先说答案

1. **在能装进上下文、也负担得起的时候，直接把全部历史放进上下文仍是最稳妥的做法**：真实 LLM 读者读完整历史得 **1.00**
   （130 个问题）；理想读者下 0.87，差距全部来自桥接概念"两个义项都在全文里"的纯度。代价是 token：1 000 个事件约 2.4 万、
   3 000 个事件约 9.5 万；6 000 个事件（约 40 万）装不进 128k 窗口，此时准确率随窗口下降（32k 0.67 → 64k 0.77 → 128k 0.81）。
2. **配置合理的结构化记忆与 World 0 在这个评测里打平，并且都在约 200–600 token 上超过了直接上下文。** 预算 1 200 时：
   按任务维护的摘要 `summary_task` 0.96、World 0 调好的版本 `world0_tuned` **0.95**、状态文档 `state_doc` 0.94、带任务标签的
   事实库 `fact_task` 0.93、直接上下文 0.87、RAG 0.74。`world0_tuned` 对 `fact_task` +0.02（10 个种子赢 9 个，Holm 校正后
   p = 0.076，不显著），对 `summary_task` / `state_doc` 0.00 / +0.01（不显著）；对直接上下文、RAG、时序图 +0.08 / +0.21 / +0.14
   （10/10，显著）。
3. **它们的区别在于各自在什么条件下崩**：
   - 按任务维护的摘要 / 状态文档**离不开正确的任务标签**：没有标签 0.55 / 0.41，错标签 0.45 / 0.30。
   - 带任务标签的事实库**吃抽取误差**：抽取错 30% 时 0.93 → 0.66。
   - World 0 **对任务标签最稳**（无标签 0.84，错标签 0.81，是用任务标签的系统里最高的），**对抽取误差最敏感**
     （0.95 → 0.58，−39%，事实库 −29%）；它用 **3 倍于事实库的 token**（590 对 189），写入贵约 500 倍（每个事件 7 ms 对 0.015 ms）。
   - 检索（RAG）写入几乎免费，但随历史变长、文本变啰嗦下降（0.77 → 0.66；每事件填充 400 token 时 0.54）。
4. **World 0 的强项与弱项**：强在多跳（依赖闭包 F1 0.98，对手按两跳配置为 0.74）、在没有或错误的任务标签下保持语境；
   弱在两跳邻域的精确率（0.56，事实库 1.00）、桥接纯度与修订的最后几个百分点（0.95 / 0.97，事实库 1.00 / 1.00）、
   以及情景细节（票据号按设计为 0）。
5. **出厂的 `Projection.render()` 仍然不适合直接放进提示词**：同一个投影用出厂渲染 0.57、用紧凑渲染 0.90；真实读者在出厂渲染下
   有一半以上的回答是概念 id（§3.5）。紧凑渲染应当成为默认（§6）。
6. **这份评测在三个地方改变了 World 0**（§7）：任务词按区分度加权并按语境拆分主张、"不再成立"的主张被撤回而不是削弱、
   读取按结算值——它们把 `world0_tuned` 从 0.59 提到 0.95。同一个"任务词没有区分度"的缺陷也让三个基线的任务过滤失效，
   基线已用同一个匹配器修复后重跑，上面所有数字都是修复后的。

## 1. 三种做法到底差在哪

| | 直接上下文 | 传统记忆（检索 / 摘要 / 事实库 / 图） | World 0 |
|---|---|---|---|
| 保存什么 | 原文 | 原文片段、摘要、抽取出的事实 | 抽取出的**概念与带类型的关系**，附信念、证据计数、成熟度、陈述时的任务 |
| 写入时做什么 | 追加 | 索引 / 摘要 / 抽取入库 | 抽取、概念解析、共现学习、衰减结算、晋升、撤回 |
| 读取时做什么 | 全部交给读者 | 相似度或实体匹配取 top-k；或整份摘要 | **激活**：从入口概念沿类型化关系扩散，再按任务、语境与多样性选出一个小的局部视图 |
| 成本随什么增长 | 历史长度（token） | 历史长度（检索）或几乎不增长（摘要 / 事实库） | 概念与关系的数量；写入最贵 |
| 主要失败方式 | 窗口装不下；被填充词稀释；每次查询都付全价 | 检索漏掉多跳；摘要 / 状态文档依赖任务标签；事实库吃抽取误差 | 抽取误差；token 比事实库多；细节没有位置；出厂渲染冗长 |
| 撤回 / 修订 | 读者自己看到"更正" | 时序图 / 事实库删除旧事实；检索靠新近度 | 撤回：旧主张退出视图，列在"No Longer Holds" |
| 一词多义（桥接） | 两义并存，读者自己分辨 | 按任务标签过滤的系统能分开 | 按主张被陈述时的任务分开，另一语境的主张列在"Seen in Other Tasks" |
| 能回答"票据号是多少" | 能 | 事实库 / 检索能 | **不能**（按设计不在职责内） |

## 2. 评测在测什么（一段话）

隐藏世界是若干个领域，每个领域是一张带类型的小概念图（依赖 / 包含 / 冲突 / 使能），另有一词多义的桥接概念、
会被修订的依赖、带票据号的事件和 25% 的闲聊；每个 seed 一个世界、一条事件流，所有系统读到同样的内容。
查询在检查点生成：`focus`（入口概念两跳内的局部视图）、`chain`（依赖闭包）、`bridge`（桥接概念在当前领域的主张，
记召回 × 语义纯度）、`stale`（被修订的依赖现在是什么，严格记分）、`detail`（票据号，不计入综合分）。金标准只含
**Agent 已被告知且仍为真**的内容。综合分 = 前四类头号指标的均值。主实验 10 个 seed（H = 1 000）；
区间为对 seed 的 95% t 区间；系统间比较按 seed 配对，精确符号翻转检验并做 Holm 校正；World 0 的 depth 与 reflect 频率
**只在 dev seeds（100–104）上选定**（depth 3、不 reflect），报告用 test seeds（0–9）。

（结构化系统只返回相关内容，不会用满预算）。

### 3.3 在什么条件下谁崩

| 条件 | `full_context` | `rag` | `summary_task` | `state_doc` | `fact_task` | `kg_temporal` | `world0_tuned` |
|---|---|---|---|---|---|---|---|
| 基准（H=1 000） | 0.87 | 0.74 | 0.96 | 0.94 | 0.93 | 0.82 | 0.95 |
| 无任务标签 | 0.87 | 0.69 | **0.55** | **0.41** | 0.82 | 0.82 | 0.84 |
| 错任务标签 | 0.87 | 0.67 | **0.45** | **0.30** | 0.77 | 0.82 | 0.81 |
| 抽取错 10% | 0.87 | 0.75 | 0.95 | 0.82 | 0.81 | 0.71 | 0.80 |
| 抽取错 30% | 0.87 | 0.75 | 0.95 | 0.66 | 0.66 | 0.58 | **0.58** |
| H = 6 000（全流 40 万 token） | 0.81 | 0.66 | 0.97 | 0.96 | 0.93 | 0.80 | 0.93 |
| 大世界（40×40，已知状态 2.3 万 token） | 0.82 | 0.75 | 1.00 | 0.99 | 0.93 | 0.84 | 0.86 |
| 每事件填充 400 token | 0.74 | 0.54 | 0.95 | 0.94 | 0.93 | 0.82 | 0.96 |
| 闲聊 75% | 0.92 | 0.82 | 0.97 | 0.95 | 0.93 | 0.86 | 0.95 |

- **任务标签**：`summary_task` / `state_doc` 用任务标签决定"哪一段在前"，标签没了或错了就把别的领域排在前面；`fact_task`
  与 World 0 把任务标签只用在"哪些主张属于当前语境"，没有标签时退化为不过滤。World 0 在这里最稳，因为语境拆分只作用于
  "在当前任务里已有主张"的概念（§7.1），错误标签指向一个与入口概念无关的任务时什么也不做。
- **抽取误差**：文本系统（RAG、全文）不受影响；按任务的摘要也不受影响，因为本评测假设读原文的总结器不犯错（它累计的是事件本身陈述的主张）——这偏向它；所有读抽取结果的系统都下降，
  World 0 降得最多（−39%，`fact_task` −29%）。多跳激活会沿着错误的边继续扩散，这是结构化视图的代价。
- **规模**：已知状态装不进一个提示词的大世界里，`summary_task` / `state_doc`（约 1 100 token）与 `fact_task`（约 200）仍然很高，
  World 0 降到 0.86（focus 0.82、bridge 0.80）——它在大世界里的邻域选择仍有改进空间。
- **历史超出窗口**（H = 6 000，理想读者只读装得下的部分）：32k 0.67、64k 0.77、128k 0.81；`fact_task` 0.93（336 token）、
  `world0_tuned` 0.93（681 token）。

|---|---|---|---|
| `full_context` | 100% | 0% | 0.54 |

| `fact_task` / `kg_temporal` | 100% | 0% | 1.00 / 0.54 |
| `kg_static` | 0% | 100% | 0.54 |
| `world0_tuned` | 97% | 0% | 0.95 |

World 0 的修订现在与事实库一样是"撤回"：`Observation.retracted_relations` 把"不再成立"的主张移出世界，3% 的问题里两者都没展示
（新主张没进入视图）。桥接纯度靠主张被陈述时的任务（`claim_tasks`）拆分，`fact_task` 用每条事实的任务标签做同样的事——在
理想抽取、标签完全准确的条件下两者都接近满分，这是评测的上限，不是真实世界的数字。

## 4. 该选哪个

| 情形 | 建议 | 依据 |
|---|---|---|
| 历史能装进窗口、每次查询付得起全价 | **直接上下文** | 真实读者 1.00；没有抽取误差、没有整理成本 |
| 历史超出窗口或要省 token，任务标签可靠 | **按任务的摘要 / 状态文档、带任务标签的事实库，或 World 0** | 0.93–0.96，彼此无显著差别；事实库最省 token（约 200） |
| 任务标签不可靠或经常缺失 | **World 0 或带任务标签的事实库**；避开按任务的摘要 / 状态文档 | 无标签 0.84 / 0.82 对 0.55 / 0.41 |
| 抽取器不可靠（p ≥ 0.2） | 文本系统（RAG、全文、按任务的摘要） | 所有读抽取结果的系统都降 29–39% |
| 需要多跳推理（依赖闭包、影响范围） | World 0（depth 3），或把事实库的遍历深度调到足够 | 闭包 0.98 对 0.74（两跳配置） |
| 需要情景性细节（票据号、原话） | 检索、事实库（保留出处）或全文 | World 0 与摘要类得 0 |
| 需要"主张可信到什么程度、哪些有争议、哪些已撤回、哪些在别的语境里" | World 0 | 其余系统不提供这些信号（本评测不计分） |

## 5. 这些结论在什么条件下成立

- **合成世界**：名字唯一、无别名 / 同义词 / 指代；任务标签与领域一一对应且（除 taskmode 研究外）完全准确；金标准由生成器定义。
  结构化基线（`fact_task`、`kg_*`）的遍历与金标准同构，偏向它们；语境拆分与任务过滤在标签完全准确时接近满分，这是上限。
- **抽取与链接是给定的**：结构化系统读生成器给的抽取结果（可注入误差，但不是真 LLM 抽取），实体链接是精确子串匹配。
  例外是 `llm` 研究（第 25、26 轮）：真实 LLM 按生产 prompt 抽取模板文本与改写文本（3 个 seed，600 个事件）。
- **读者阶段是第三版的**（§3.5）。
- **任务匹配对所有系统相同**：World 0、`fact_task`、`state_doc`、`summary_task` 用同一个区分度加权的匹配器与同一个阈值 0.5。
- **World 0 的其余功能没有被评价**：视角、reflect 的社群与色场步骤、概念身份与合并 / 拆分、遗忘的收益、跨会话漂移。
- 紧凑格式是作者写的；token 数是估计（`chars/4` 作为敏感性并列报告）。

## 6. World 0 该改什么（按这份评测的证据排序）

1. ~~**紧凑渲染成为默认**~~ ✅ 第 24 轮（分析文档 §7.26）（或至少是 `render(style="compact")`）：出厂渲染 0.57、紧凑 0.90；出厂渲染按成熟度分节并打印 id 与链接列表。
   已完成：`Projection.render()` 默认即紧凑形式，`world0_compact` / `world0_tuned` 现在直接用库里的渲染；1200 token 下分数不变
   （0.90 / 0.95），token 多 14–18%，因为撤回与"其他任务"两节也进了提示词。`world0` 行保留完整渲染以便对比。

## 7. 这份评测改变了什么（第三版 → 第四版）

第三版的结论是 World 0 落后带任务标签的事实库 0.22（0.59 对 0.82，10/10 种子）。复查"为什么任务标签对 World 0 毫无影响"时
发现三件事（分析文档 §7.24、§7.25，论文 §3.2、§4.4、§7.3）：

1. **任务词没有区分度**（World 0 与三个基线都有）。评测里的任务全是"〈领域〉 work"；按词计数的匹配让任意两个任务至少匹配 0.5，
   World 0 的任务条件、`fact_task` 的任务过滤、`state_doc` 的排序都因此失效。修复：按词在全部任务标签中的区分度加权
   （`TaskVocabulary`，$\ln\frac{L+1}{d+1} + 0.01$），阈值 0.5；**基线用同一个匹配器**（`benchmarks/longrun/systems.py`
   `TaskMatcher`）。仅这一项让 `fact_task` 从 0.82 升到 0.93（桥接 0.54 → 1.00）。
2. **投影不看主张的语境**（World 0）。概念选择随任务变化，但"选中概念之间的全部关系"都进入视图。修复：主张的语境是它被陈述时
   的任务；在当前任务里已有主张的概念，其别处的主张移到 `other_contexts`。
3. **修订只削弱旧主张**（World 0）。"不再依赖"走的是否证，旧主张一直在视图里（严格修订得分 ≈ 0，真实读者 100% 提到了它）。
   修复：撤回（`retracted_relations`）。评测适配器从此把"更正"作为撤回传入——与事实库、时序图删除旧事实同样使用抽取结果里的撤回。

此外，读取改为结算值、并把已死的边与概念视为不存在（论文推论 3.2′），使视图与 reflect 的调度无关。一次独立评审找出了第一版实现
的八处缺陷，均已修复并有回归测试。

| | 第三版 | 第四版 |
|---|---|---|
| `world0_tuned` 综合 | 0.59 | **0.95** |
| `fact_task` 综合 | 0.82 | 0.93 |
| `world0_tuned` 对 `fact_task` | −0.22（0/10） | +0.02（9/10，不显著） |
| `world0_tuned` 桥接 / 修订 | 0.52 / 0.00 | 0.95 / 0.97 |
| `world0_tuned` 无 / 错任务标签 | 0.59 / 0.61 | 0.84 / 0.81 |
