# World0 Research Portal

Static research dashboard for the World0 project: <https://redbson.github.io/world0/research-portal/>

Every page is generated by `build.py` from the JSON records in `data/`. Edit the
records, run the build, commit both. Never edit generated HTML by hand. Pages are
bilingual (EN / 中文 / both, chosen in the masthead and remembered per browser).

## Where it is published

| Setting | Value |
|---|---|
| Pages source | branch `agent/blissful-bohr-j9jvwm`, folder `/ (root)` (Settings → Pages → Deploy from a branch) |
| Portal directory | `research-portal/` on that branch |
| Dashboard | `https://redbson.github.io/world0/research-portal/` |
| Daily report | `https://redbson.github.io/world0/research-portal/reports/YYYY-MM-DD.html` |
| Weekly synthesis | `https://redbson.github.io/world0/research-portal/weekly/YYYY-Www.html` |

The branch is built by Jekyll (the rest of the repository is Markdown and code).
Jekyll copies HTML and JSON files that have no front matter unchanged, so the
portal needs no Jekyll configuration. Do not add front matter to portal files.

## Layout

```
build.py                 generator and validator (Python standard library only)
data/papers.json         every paper ever recorded, one record per canonical id      (edit)
data/hypotheses.json     hypotheses with their status history                         (edit)
data/experiments.json    experiments with their status history                        (edit)
data/reports/DATE.json   one record per research session                              (add)
data/weekly/WEEK.json    one record per weekly synthesis                              (add)
data/research_state.json publishing target and verified deployments (edit
                         `deployments` only; the rest is derived)
data/i18n_zh.json        Chinese renderings of visible strings                        (edit)
data/latest.json         derived: the latest session's findings and insights
index.html               derived: dashboard, sections A–F
reports/DATE.html        derived: daily report, sections 1–10
papers/ID.html           derived: one analysis page per paper
weekly/WEEK.html         derived: weekly synthesis
assets/css/style.css     theme
assets/js/app.js         progressive enhancement (filters, live Pages status)
```

## A research session

1. Check out the publishing branch and read the existing records:
   `git fetch origin agent/blissful-bohr-j9jvwm && git checkout -B agent/blissful-bohr-j9jvwm origin/agent/blissful-bohr-j9jvwm`.
2. Verify the previous session's deployment (see *Deployment*) and append it to
   `research_state.json` → `deployments`.
3. Do the research. Add new papers to `papers.json` (deduplicate by id: a paper
   already recorded gets today's date appended to `seen`, not a second record).
4. Write `data/reports/YYYY-MM-DD.json`. Register new hypotheses and experiments;
   record status changes by appending to `history`.
5. Add Chinese renderings: `python3 research-portal/build.py --missing-zh` prints
   the visible strings without one as JSON; add them to `data/i18n_zh.json`.
6. `python3 research-portal/build.py` — validates every record, compares them
   with the last commit, and regenerates the pages. Fix every reported problem.
7. `python3 research-portal/build.py --check` must print `ok`.
8. Commit only `research-portal/` with the message
   `research: daily intelligence YYYY-MM-DD`, then
   `git push origin agent/blissful-bohr-j9jvwm`. Never force-push; if the push is
   rejected, fetch, rebase onto `origin/agent/blissful-bohr-j9jvwm`, rebuild, push.

Do not create other branches or pull requests for portal output: the Pages site
is built from this branch only, and records kept anywhere else are lost to the
next session.

## Records

Identifiers are stable and never reused.

- **Paper** `id`: `arxiv:NNNN.NNNNN`, `doi:10.x/...`, or `title:lower-case-slug`
  when no canonical identifier can be found. Required: `title`, `authors` (or
  `null`), `published` (`YYYY`, `YYYY-MM` or `YYYY-MM-DD`), `source`, `url` (http(s)
  or `null`), `category`, `relevance` (0–1, the research agent's judgement),
  `deep` (true only for a full analysis), `verification` (how the record was
  obtained, e.g. `full-text`, `search-summary-only`, `title-only`), `first_seen`,
  `seen` (dates of the sessions that discussed it). Analysis fields: `thesis`,
  `foundations`, `mechanism`, `evidence`, `limitations`, `implications` (text, or
  an object with `components`, `improvements`, `complexity`, `benefits`, `risks`),
  `assessment` (text, or an object with `author_claims`, `observations`,
  `interpretation`, `speculation`).
- **Hypothesis** `H-NNN`: `hypothesis`, `motivation`, `status` (PROPOSED,
  UNDER_TEST, SUPPORTED, REFUTED, INCONCLUSIVE), `evidence` (strings; a leading
  paper id becomes a link), `next_experiment` (`E-NNN` or `null`), `history`
  (`[{date, status, note}]`, the last entry carries the current status).
- **Experiment** `E-NNN`: `hypothesis`, `description`, `status` (PENDING, RUNNING,
  COMPLETED, ABANDONED), `result` (required when COMPLETED), `artifact`, `history`.
- **Report** `data/reports/YYYY-MM-DD.json`: `date`, `generated` (UTC,
  `YYYY-MM-DDTHH:MM:SSZ`), `status` (COMPLETE, PARTIAL, FAILED), `status_note`,
  `importance` (HIGH, MEDIUM, LOW), `direction` (one line), `summary`,
  `findings` (1–5; the first three are the dashboard's key findings; each has `id`
  `F-N`, `title`, `category`, `discovery`, `relevance`, `strength`, `action`,
  `paper`), `radar` (paper ids discussed), `deep` (paper ids analysed in full),
  `deep_note`, `insights` (one per area: Dynamic Ontology, Self-Model, Dream
  Mechanism, World Models, Cognitive Architecture; `label` CONFIRMED, SUPPORTED,
  EXPERIMENTAL or SPECULATIVE), `hypotheses`, `experiments`, `recommendations`,
  `knowledge_updates`, `open_questions`, `priorities`, `queries`, `sources` and
  `links` (`[{title, url}]`), `editorial_notes`.
- **Weekly** `data/weekly/YYYY-Www.json`: `week`, `generated`, `from`, `to`,
  `summary`, `trends`, `mechanisms`, `contradictions`, `evidence_changes`,
  `opportunities`, `gaps`, `experiment_priorities`, `reports` (dates covered).
- **Deployment** (in `research_state.json`): `{commit, verified_at, conclusion,
  run}`.

Evidence labels describe the support a finding has in the literature, not whether
World0 implements it. Never invent missing results: write "not recovered".

## Chinese

`data/i18n_zh.json` maps an exact English string to its Chinese rendering; the
interface labels are built into `build.py`. Write the key exactly as the record
says it; for multi-paragraph text, translate the whole string and keep the same
blank-line paragraph breaks. A string without a rendering is shown in English in
every language mode. Do not translate paper titles, author names, identifiers or
search queries. Translations are presentation: they never change a record, and a
changed record needs its new English string translated again.

## History is append-only

`build.py` compares the records with the last commit (`git show HEAD:...`) and
refuses to build when:

- a paper, hypothesis, experiment, report or weekly record was removed;
- a `history` list was rewritten instead of appended to;
- a tracked field changed (a paper's analysis or metadata, a hypothesis's text or
  evidence, an experiment's description or result) without an appended history
  entry whose `previous` object holds the old value;
- a committed report or weekly synthesis changed (append to `editorial_notes`
  instead);
- a date was removed from a paper's `seen` list, or `deployments` was rewritten.

`--no-history` skips this comparison; use it only for a first build.

## Safety

All text is escaped when it is inserted into HTML, and only `http(s)` URLs become
links, so research content cannot inject markup or scripts. Pages load no
third-party script; the only external requests are the web fonts (optional) and
the public GitHub API call that shows the live Pages status (optional).

## Deployment

A push to `agent/blissful-bohr-j9jvwm` starts the *pages build and deployment*
workflow. Verify it with

```
gh api "repos/redbson/world0/actions/runs?branch=agent/blissful-bohr-j9jvwm&per_page=1"
```

The run is the deployment of the pushed commit when its `head_sha` equals the
commit, `status` is `completed` and `conclusion` is `success`. A commit alone is
not a deployment. If the site itself cannot be fetched from the research
environment, say so and rely on the workflow run.
